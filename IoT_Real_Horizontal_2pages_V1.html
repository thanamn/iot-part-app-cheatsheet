  • IoT / IoE = เครือข่ายของ things + platform ที่คุยกันเองผ่าน wireless โดยไม่ต้องมีมนุษย์สั่ง (without human intervention) → ได้ efficiency, performance, safety
  • 3 ประโยชน์หลัก: Communication · Control & Automation · Cost Saving
  • 9 คุณลักษณะ (ท่องให้ได้): Connectivity · Intelligence · Dynamic Nature · Enormous Scale · Sensing · Heterogeneity · Security · Unique Identity · Integration into Information Network

ไปป์ไลน์: Frame capture (OpenCV) → Face Detection (Haar Cascade) → Privacy Blur → Logging → Flask Web Stream

  • สายกล้อง Pi = MIPI CSI-2 serial (ไม่ใช่ USB/UVC, I²C, SPI, HDMI)
  • สตรีมขึ้นเบราว์เซอร์ = Flask + HTTP (MJPEG) ไม่ใช่ MQTT/WebSocket/gRPC
  • เช็ค OS cat /etc/os-release · เปิดกล้องรุ่นเก่า raspi-config → Interfacing Options → Camera
  • คำสั่งกล้อง: Bullseye libcamera-hello / -jpeg -o x.jpg / -vid -o x.h264 / -raw → Bookworm เปลี่ยนคำนำหน้าเป็น rpicam-*

HAAR CASCADE

  • Sliding Window + Haar Filters ไถทั่วภาพ
  • Integral Image → หาผลรวมพื้นที่เร็ว (fast sum)
  • Cascade Stages → ด่านแรกตัดพื้นหลังทิ้งไว ๆ
# ต้องแปลง grayscale ก่อนเสมอ
f = cv2.CascadeClassifier(cv2.data.haarcascades +
    'haarcascade_frontalface_default.xml')
faces = f.detectMultiScale(gray,
  scaleFactor=1.1,  # ↑ เร็วขึ้น แม่นลง
  minNeighbors=5,   # ↑ false positive ลด
  minSize=(30,30))
for (x,y,w,h) in faces:
  roi = frame[y:y+h, x:x+w]
  frame[y:y+h, x:x+w] = cv2.blur(roi,(25,25))

fps: processing time/เฟรม = t_end − t_start · fps = 1 / processing time (s) → 50 ms = 20 fps · ในแล็บค่า default ช่วงที่หน้าเริ่มเบลอ = 11–25 fps

Spatial Filtering vs Convolution

  • Filtering = ไถ kernel ทับภาพ หาผลรวมของผลคูณ → ได้ correlation ของภาพกับ kernel
  • Convolution = เหมือนกัน แต่ พลิก (mirror) kernel 180° ก่อน → output คล้าย kernel · kernel สมมาตร = ผลเท่ากัน · ใช้ cv2.filter2D
  • Box/Average (cv2.blur) = เบลอ · kernel ใหญ่ขึ้น 5×5 → 15×15 = เบลอแรงขึ้น + ช้าลง (ไม่ใช่คมขึ้น ไม่ใช่ fps ขึ้น)
  • Gaussian = เบลอนุ่ม ถ่วงน้ำหนักกลางมาก
  • Laplacian = เหลือแต่ขอบ ไม่เหลือรายละเอียดอื่น (อนุพันธ์อันดับ 2) ขยาย noise
  • Sobel/Prewitt = ขอบตามแกน x หรือ y · Sharpen = คมขึ้น

Lab 2 · OCR อ่านป้ายทะเบียน

เปลี่ยน raw image → ข้อมูลที่ใช้ได้ · ไลบรารี = EasyOCR (ไม่ใช่ OpenCV/NumPy/Matplotlib/Pandas) · โชว์ผลบนเว็บ Flask/Gradio · ใช้กับ smart logistics, smart parking, document digitization

4 กลุ่ม OCR

  • Basic Tesseract 5–20 MB · EasyOCR 30–80 MB → ฟรี เบา CPU ได้ แต่แม่นน้อย ฟอนต์ไทยแย่ ไม่วิเคราะห์ layout · รันบน Pi/edge
  • Cloud Google Vision, Azure OCR, AWS Textract → แม่นหลายภาษา ต่อง่าย แต่ต้องมีเน็ต + มีค่าใช้จ่าย + เสี่ยง privacy
  • Advanced PaddleOCR mobile 8–20 MB / server 100–300 MB · MMOCR 50–200 MB · DocTR 200–400 MB · Keras-OCR 70–120 MB → detection+recognition, layout ซับซ้อน แต่หนัก ต้อง GPU
  • Native/Mobile iOS Vision, Android ML Kit → on-device offline แต่ผูกแพลตฟอร์ม

พารามิเตอร์ EASYOCR

  • text_threshold เกณฑ์ความมั่นใจของตัวอักษร · เจอขยะมั่ว ๆ ทั่วภาพ → เพิ่มค่านี้
  • low_text ขอบล่างคะแนนข้อความ · ลด = จับตัวจาง ๆ ได้มากขึ้น (ขยะมากขึ้น)
  • link_threshold เชื่อมตัวอักษรเป็นคำ · gpu=False บังคับ CPU
  • allowlist จำกัดชุดอักขระ (ไทย+เลข) → ลดการอ่านผิดประเภท ไม่ได้ช่วยความเร็วเซิร์ฟเวอร์ / contrast / การหมุน
r = easyocr.Reader(['th','en'], gpu=False)
out = r.readtext(img, allowlist=ALLOWLIST,
       text_threshold=0.7, low_text=0.4)
# out = [(bbox, text, confidence), ...]

เร่งความเร็ว: crop ROI ป้าย / ย่อภาพ / grayscale · ทำ OCR ทุก N เฟรม · โหลด Reader ครั้งเดียวนอกลูป · ใช้ allowlist + โมเดลเบา · ยกงานหนักขึ้น cloud (hybrid)

เมตริกที่ต้องเลือกให้ถูก

  • Accuracy = % ที่ถูกทั้งหมด (exact match) → ไม้กั้นเปิดเฉพาะเมื่ออ่านป้ายถูกทุกตัว ผิดตัวเดียวไม่ผ่าน = Accuracy
  • CER = (S+D+I)/N ตัวอักษร · CER 15% = ตัวอักษร 15% ไม่ตรง (ไม่ใช่ถูก 85% ไม่ใช่เฟรมหลุด ไม่ใช่ fps/latency) · WER = ระดับคำ
  • Precision TP/(TP+FP) ที่ทายว่าใช่ ถูกจริงกี่ % · Recall TP/(TP+FN) ของจริงจับได้กี่ % · F1 = 2PR/(P+R) ใช้เมื่อคลาสไม่สมดุล
  • BLEU = งานแปล/generate text · OKS = งาน keypoint/pose — ทั้งคู่ไม่ใช่เมตริก OCR ป้ายทะเบียน
  • ความเชื่อถือได้ของระบบเตือน = % ของ alert ที่ส่งถึงสำเร็จภายใน 5 วินาที (ไม่ใช่จำนวนผู้ใช้ ไม่ใช่รอบชาร์จแบต)
  • Latency / fps = ความเร็ว · uptime % = reliability

def classifier(i_t,i_p, m_t,m_p, r_t,r_p, p_t,p_p):
    up = lambda t,p: t < p     # เหยียด
    f = [up(i_t,i_p), up(m_t,m_p),
         up(r_t,r_p), up(p_t,p_p)]
    if not any(f): return "ROCK"
    if all(f):     return "PAPER"
    if f[0] and f[1] and not f[2] and not f[3]:
        return "SCISSORS"
    return ""

กับดักที่พลาดบ่อย

  1. High latency ไม่ใช่คุณลักษณะ IoT — แต่ Scalability คือ (Enormous Scale)
  2. Desktop PC ไม่ใช่ edge device · Jetson Nano เป็น
  3. กล้อง Pi = MIPI CSI-2 · สตรีม = Flask + HTTP
  4. kernel ใหญ่ขึ้น = เบลอแรงขึ้น · Laplacian = เหลือแต่ขอบ
  5. Convolution พลิก kernel · filtering ไม่พลิก
  6. CCTV ที่ถูก: on-device buffer สั้น → edge จำหน้า + กรอง event → cloud analytics + เก็บยาว
  7. D2C = ไม่ผ่าน gateway — จับคำว่า "directly" ในโจทย์
  8. ข้อดี Cloud-centric = พลังประมวลผล + เทรน ML ไม่ใช่ latency ต่ำ/privacy
  9. ข้อเสีย Cloud OCR = network dependency + privacy
  10. ขยะ OCR ทั่วภาพ → เพิ่ม text_threshold
  11. Innovation = บริการ/มูลค่าใหม่ ไม่ใช่ if-else ไม่ใช่อัปไฟล์ขึ้น cloud
  12. "You Win!" ขึ้นทันที = Notification ไม่ใช่ Visualization
  13. MediaPipe = 21 จุด · นิ้วเหยียด TIP.y < PIP.y
  14. UX metric = เวลาเรียนรู้การใช้แอป
  15. โมเดลเก่าเจอข้อมูลใหม่แล้วแย่ = Maintainability
  16. Explainability มีไว้ให้คนเชื่อถือผล ไม่ใช่ลด latency/storage
